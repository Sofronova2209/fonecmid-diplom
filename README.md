# Дипломный проект профессии «1C-программист: с нуля до middle»
 
## Кастомизация конфигурации «Управление IT-фирмой для компании «Ваш компьютерный мастер»

### Цель дипломного проекта

Разработать и подготовить к эксплуатации новый функциональный блок в конфигурации «Управление IT-фирмой».

Вам нужно:

- реализовать новые подсистемы «Работа с заявками клиентов» и «Расчёт управленческой зарплаты» в соответствии с требованиями заказчика,
- подготовить отчёты по новой функциональности,
- оформить инструкцию по начальной настройке,
- подготовить автотест для проверки корректности работы подсистемы «Работа с заявками клиентов»,
- загрузить результат работы в новый репозиторий на GitHub.

------

### Чек-лист готовности к работе над проектом

1. Установите [платформу 1С:Предприятие 8.3.27](https://developer.1c.ru/applications/Console?state=community).
2. Скачайте и установите 1С:EDT [последней актуальной версии](https://releases.1c.ru/version_files?nick=DevelopmentTools10&ver=2024.2.5).
3. Зарегистрируйтесь на github.com и создайте форк от этого репозитория.
4. С помощью 1С:EDT клонируйте свой форк репозитория.

Если все этапы чек-листа пройдены, можете начинать работу над проектом. Успехов.

### Описание задания

Компания «Ваш компьютерный мастер» использует конфигурацию «Управление IT-фирмой» от стороннего поставщика. Вам поставлена задача добавить в конфигурацию модуль для работы с заявками на обслуживание клиентов и модуль для расчёта управленческой заработной платы.

Исходная версия конфигурации размещена в [этом репозитории](/fonecmid-diplom). Для доработки конфигурации нужно использовать 1C:EDT. При доработке конфигурации максимально задействуйте функциональность библиотеки стандартных подсистем.

Для добавленных объектов, реквизитов, методов используйте префикс ВКМ_. Если меняется программный код существующих методов, изменения должны быть выделены комментариями.

Все добавленные объекты должны быть размещены в новой служебной подсистеме ВКМ_ДобавленныеОбъекты. В добавленных объектах не должно быть ошибок, выявляемых встроенным механизмом проверки 1C:EDT.

Для передачи результата изменённую конфигурацию загрузите в отдельный репозиторий на [github.com](https://github.com). Чтобы результаты работы можно было проверить, репозиторий должен быть публичным.

Вместе с результатами работы должны быть переданы инструкция по начальной настройке новой подсистемы и сценарий для автоматизированного тестирования модуля работы с заявками клиентов.

В блок Releases репозитория должен быть добавлен dt-файл демонстрационной базы с введёнными тестовыми данными, которые показывают работу всех механизмов системы.

- 1-я неделя. Разработка подсистемы «Работа с заявками клиентов».

### Правила сдачи работы

Решение нужно передать в виде ссылки на публичный репозиторий на github.com, в котором размещены:

1. Исходный код доработанной конфигурации в формате 1C:EDT.
2. Сценарий автотеста и инструкция по запуску автотеста.
3. Инструкция по начальной настройке доработанной конфигурации.

### Критерии оценки

Зачёт по дипломной работе можно получить, если работа соответствует критериям:

1. Репозиторий содержит исходный код конфигурации в формате 1C:EDT.
2. Функциональность конфигурации не имеет существенных ошибок и соответствует техническому заданию.
3. В добавленных объектах нет ошибок, выявляемых проверками 1C:EDT с набором плагинов и составом проверок по умолчанию.
4. Автотест запускается и соответствует техническому заданию.
5. Инструкция по начальному запуску описывает шаги, необходимые для начала использования доработанной конфигурации.
6. Демонстрационная база содержит достаточный набор данных, соответствующий требованиям.

### Введение
Данная инструкция содержит рекомендации для специалистов предприятия по первичной настройке и запуску внедряемых доработок. Все настройки должны быть произведены в рабочей информационной базе предприятия. Это необходимо для корректного функционирования механизмов учёта, интеграции, автоматизации расчётов, создания актов и формирования отчётов.

### 1. Первичная настройка

Заполнение констант

- Откройте раздел Администрирование → Константы.

- Заполните реквизиты:

Телеграм_Токен — токен управления телеграм-ботом

Телеграм_IDГруппы — идентификатор группы для оповещений

НоменклатураАбонентскаяПлата — номенклатура для строк по абонплате

НоменклатураРаботыСпециалиста — номенклатура для работ исполнителя

Проверьте, что все значения корректны (при отсутствии вы получите ошибку при автозаполнении документов).

- Заполнение справочников

Минимум 5 элементов должны быть заведены в каждый ключевой справочник: Клиенты, Договоры, Сотрудники, Номенклатура, Организации, Пользователи, Специалисты, Профили доступа, Присоединенные файлы, Роли.

Наличие демонстрационных элементов обеспечит отработку всех сценариев.

### 2. Назначение ролей и профилей

Перейдите в Настройки пользователей и прав.

Получателям доступа выберите соответствующие роли из списка:

- Специалист

- Менеджер

- БухгалтерИТФирмы

- КадровикРасчетчик

- Администратор

Каждому пользователю назначьте соответствующий профиль группы доступа согласно его функциональной роли.

Настройка дополнительных объектов

Проверьте, что в Командном интерфейсе присутствуют все новые команды.

Проверьте справочник для присоединения файлов, настройте определяемые типы для объектов файла и ссылки на владельцев.

### 3. Запуск и работа с механизмами

1. Работа с документом Обслуживание Клиента

При создании нового документа заполните следующие реквизиты:
Клиент, Договор, Специалист, Дата, Время начала/окончания (план), Описание проблемы, Комментарий.

В табличной части «Выполненные Работы» перечислите: описание работы, фактически потраченное время, часы к оплате клиенту.

Для загрузки файлов/документов воспользуйтесь справочником присоединённых файлов.

При проведении документа:

Проверяется, что выбран договор с типом абонентской платы, а дата попадает в сроки действия договора.

Начисления по работам формируются автоматически; сумма рассчитывается по ставке часа из договора.

При первом проведении (или изменении даты, времени, специалиста) в справочник уведомлений для телеграм-бота добавляется сообщение.

Для корректной интеграции с Telegram требуется заполненные верные константы.

Доступ к документам гарантирован соответствующей ролью (см. раздел "Права").

2. Реализация товаров и услуг

Убедитесь в правильной привязке договора к типу "абонентская плата".

Для автозаполнения нажмите кнопку «Заполнить» на форме документа:

Если не заполнены константы-номенклатуры — система выдаст ошибку.

Если заполнено — строки добавятся автоматически: абонплата и суммы за работы.

Доступна печать акта оказанных услуг в формате mxl. Макет доступен для редактирования.

Для массового создания реализаций используйте обработку "МассовоеСозданиеАктов" (см. следующий раздел).

3. Массовое создание актов

В обработке выберите период (месяц).

Табличная часть автоматически заполнится списком договоров и сгенерированными реализациями за период.

Создание актов выполняется через механизм длительных операций; повторно создания за месяц не происходит.

Проверьте, что у всех договоров стоят корректные суммы абонентской платы и выполнения работ.

Проведение актов запустится с использованием стандартного метода заполнения и контроля корректности.

4. Зарплата и взаиморасчёты с сотрудниками

Введите оклады и проценты по работам для всех сотрудников и специалистов (регистр сведений «Условия Оплаты Сотрудников»).

Расчёт выполняется через документы «Начисление Заработной Платы» и «Начисление Фиксированных Премий».

Премии заводятся отдельным документом.

Выплаты вносятся документом «Выплата Зарплаты», который заполняется автоматически по остаткам.

Все начисления, удержания и выплаты автоматически формируют движения по соответствующим регистрами (в том числе «Взаиморасчеты С Сотрудниками»).

5. Планирование и контроль отпусков

Используйте документ «График Отпусков» для ввода отпусков сотрудников на год.

Строки превышающие 28 календарных дней подсвечиваются в форме.

На дополнительной форме «Анализ Графика» доступна диаграмма Ганта для удобного визуального контроля.

Проанализируйте возможные пересечения и скорректируйте график.

6. Отчёты

Пользуйтесь стандартными отчетами:

Выработка специалистов — по часам и начислениям за указанный период.

Анализ выставленных актов — по клиентам, договорам, фактической сумме по работам.

Расчёты с сотрудниками — по начислениям, выплатам, задолженности.

Расход запланированных отпусков — по плану и факту дней отпуска.

Отчеты используют данные только регистров.

Доступ к отчетам определяется профилем и ролью пользователя.

### 4. Интеграция с Telegram

Укажите валидный токен и ID группы в константах!

Проверяйте корректность в справочнике уведомлений.

Модуль интеграции отправляет сообщения, связанные с ключевыми событиями документов.



### Важно

Минимальные требования к версии платформы 1С: 8.3.Х и совместимости с используемыми подсистемами (БСП, подключаемые команды).

При изменении состава справочников и типовых констант проверьте заполнение полей, иначе возможны ошибки автозаполнения, интеграции и проведения документов.

Два раза запускать обработку массового создания актов за один месяц нельзя.
